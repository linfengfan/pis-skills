# 项目画像初始化（前端 fe-profile / 后端 be-profile）

探测仓库的结构与约定，生成画像文件。画像是 ②③④⑥⑦ 各阶段「项目画像」入参的唯一来源；没有画像，方案和评审只能按通用最佳实践打分，规范一致性维度会失真，⑦ 也不知道用什么命令取证。

## 触发条件

- ⓪ 工作区确认后，某个泳道的仓库缺画像（`tools/workspace-detect.js` 输出里 `repos[].profile` 为 null）
- 用户要求重新生成 / 刷新画像

## 落盘位置

| 泳道 | 文件 | 模板 |
|------|------|------|
| fe | `<前端仓>/.claude/fe-profile.md` | `templates/项目画像模板.md` |
| be | `<后端仓>/.claude/be-profile.md` | `templates/后端画像模板.md` |

画像随仓库提交，团队共享。

---

## 前端探测清单

### 1. 技术栈
读 `package.json`、`.nvmrc`、构建配置：框架与版本 / UI 库 / 语言 / 构建 / 测试 / 状态管理 / 包管理器与 Node 版本。读 `CLAUDE.md` / `AGENTS.md` / `.cursor/rules/*` 提取已声明规范，列进「规范文件索引」。

### 2. 门禁命令
读 `package.json` scripts：

| 用途 | 识别目标 | 缺失时 |
|------|----------|--------|
| lint | lint / eslint | 标注；只对改动文件跑 |
| format | format / prettier | 可省略 |
| type-check | type-check / vue-tsc / tsc --noEmit | 标注 |
| test | test / test:unit / vitest | 标注「无自动化测试」 |
| e2e | test:e2e / e2e / playwright / cypress；`playwright.config.*` / `cypress.config.*` 是否存在 | 标注「无 e2e 框架」，⑦ 将退化为浏览器手工验证或 unverified |
| dev server | dev / serve / start | 标注 |
| build | build | 标注耗时量级 |

每个命令标耗时量级（快 <30s / 中 30–120s / 慢 >120s），用真实计时。e2e 额外记录用例目录、命名约定、本地 baseUrl。

### 3. 接口层与环境地址
搜索 `src/api/` `src/services/` `src/request*` `src/http/`：请求封装位置、响应码约定（与后端统一响应体对齐）、错误处理、鉴权注入、环境切换。读 `.env.development` 等环境文件：`VITE_APP_API_TARGET` 之类的联调网关地址写进「环境地址」——⑤⑦ 要用。找一个近期接口函数作新增接口样例；记录 Mock 层 / fixtures 约定（④ 按契约生成 Mock 放哪）。

### 4. 路由与页面
路由定义位置、注册模式、页面目录映射规则、新增页面标准步骤。

### 5. 状态管理
store 位置、模块划分、什么进全局 / 什么留视图级、持久化约定。

### 6. 公共 / 高风险区域
引用计数：被大量引用的公共组件、工具、请求层、路由守卫、根组件。Top 5。

### 7. 参考实现
复杂页面 / 简单页面 / 表单页 / 列表页各一个近期良好实现。

### 8. 环境与工具
codegraph、知识库是否存在；部署流水线（`.workflow/*.yml`）的触发分支——它是 `repos[fe].base` 的依据。

## 后端探测清单

### 1. 技术栈
读 `pom.xml` / `build.gradle` 与配置：JDK、框架与版本、ORM、数据库与连接池、缓存与锁、消息（或 outbox）、配置中心、鉴权上下文、格式化 / 静态检查工具、**是否有 OpenAPI 文档**（没有则契约只能是 Markdown）。

### 2. 门禁命令
从构建文件与 `CLAUDE.md`「常用命令」提取：build / lint（spotless:check）/ test（`-pl <module> -am`）/ contract-test / integration-test / local-run。**明确写清后端能否本地起完整应用**；不能就写「不可本地运行」，⑦ 据此把需要 DB 的路径标 unverified。统计 `src/test` 下测试文件数量与典型 `@WebMvcTest` 位置。

### 3. 模块 → 流水线 → 环境
读根 `pom.xml` 的 `<module>` 列表与 `.workflow/*-dev.yml`：每个模块的职责（CLAUDE.md 模块职责表）、对应流水线文件、触发分支、`paths` 过滤、dev 域名（从 K8s 配置或前端 env 推断，推断的标「待确认」）。标出公共模块（common / starter / gateway / 网关上下文）——改它们触发多条流水线。网关入口地址单独一行。`tools/workspace-detect.js` 会给出初稿。

### 4. 分层与入站类型
从 `CLAUDE.md` / `crs/layered-architecture.md` 抄录：入站类型表（包 / 路径前缀 / 身份来源）、Service / Manager / Mapper 职责、跨模块协作允许的机制、禁止的依赖。

### 5. 公共组件
统一响应体与成功码、错误码入口、全局异常处理器、基础实体与通用字段、登录上下文、分布式锁 / 幂等组件——各自的类名与位置。

### 6. 接口约定（契约评审基准）
路径命名风格、对外 ID 规则、DTO / VO 形态与放置包、分页约定、时间 / 金额格式、新接口是否需配网关 route、开放接口权限上下文字段。

### 7. 数据库约定
表名前缀、通用字段清单、业务主键规则、身份字段存什么、迁移脚本位置与方式、禁止事项（物理删除等）。

### 8. 事务与事件
多表写事务注解约定、事务内禁止的操作、异步与通知走 outbox 的约定、幂等要求、定时任务约束。

### 9. 高风险区域与参考实现
共享表、公共模块、网关 route 配置；典型 Controller + DTO/VO、含事务的 Service、Mapper、`@WebMvcTest`、迁移脚本各一个。

### 10. 规范文件索引
`CLAUDE.md` / `AGENTS.md` / `crs/*.md` / `.cursor/rules/*.mdc` / 项目级编码 skill / `doc/*.md`，每个一句用途。

---

## 流程

1. 按清单逐项探测（可并行派两个只读子 agent，一仓一个）
2. 整理画像草稿
3. 展示关键决策点：门禁命令取舍、后端能否本地跑、模块与流水线对应、高风险区域、参考实现
4. **过闸门**：用户确认后写入各仓 `.claude/` 下

## 纪律

1. 探测不到的标「未探测到」——禁止用通用常识填充
2. 耗时量级用真实计时，域名推断的标「待确认」
3. 用户手工补充的内容，重跑时不得删除
4. 画像不写任何凭证明文
