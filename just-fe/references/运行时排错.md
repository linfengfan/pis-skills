# 子 agent 调用约定与排错

> 本 Skill 只有一种执行方式：**编排者（主 agent）读阶段卡，派子 agent 执行**。本文是子 agent 调用的参数形态、结构化输出约定与报错对照。遇到子 agent 工具报错先来这里查。

## 一、子 agent 工具参数形态

`Agent` / `Task` 类工具的必填参数是 `description`、`prompt`、`subagent_type`。**没有** `label` / `schema` / `phase`——那是阶段卡里的叫法，照搬给工具就是 `Invalid tool parameters`。

| 阶段卡里写的 | 工具参数 |
|-------------|----------|
| `label`（如 `requirement-analysis`） | `description`（3～5 个词，如 `triage requirement`） |
| prompt 各节 | `prompt`（按阶段卡原样拼接完整） |
| `*_SCHEMA` | 追加到 `prompt` 末尾的 schema 尾注（见下），返回后你自己解析 |
| — | `subagent_type`：填当前环境工具描述里列出的通用类型（Claude Code 是 `general-purpose`，Cursor 是 `generalPurpose`，**以工具描述为准，不凭记忆编**）。④⑤⑦ 要写文件 / 跑命令，必须用有写权限的类型 |

**schema 尾注**（追加在每个需要结构化返回的 prompt 末尾）：

```
---
回复末尾输出一个 ```json 代码块，严格符合以下 JSON Schema，不要输出 schema 之外的键：
<阶段卡里的 schema 原文>
```

**解析**：从子 agent 回复中取**最后一个** ```json 代码块 `JSON.parse`；失败则原样重试该子 agent 一次；再失败按阶段卡的兜底处理（一般是按空对象 / 未返回维度处理），并在报告「待确认」里注明「<label> 未返回结构化结果」。

**并行**：阶段卡标了并行的评审员，必须**同一条消息里**发出全部调用；禁止串行——串行会让后面的评审员看到前面的结论，独立性归零。返回结果**按派出顺序（下标）对应维度**，不信 agent 回填的 `dimension` 字段。

**隔离**：不要把 A 维度的结论写进 B 维度的 prompt；不要在主上下文里自己当评审员——主上下文只做汇总。

**环境里有同名子 agent 时**（如 `~/.cursor/agents/` 下的 `fe-dev`、`code-audit`）：它们是独立维护的个人人设，可能与本 Skill 阶段卡里的人设不同步。**阶段卡的人设为唯一准绳**——要么按卡拼 prompt 派通用类型，要么确认同名 agent 内容与卡一致后再用。

## 二、报错对照表

| 报错 / 现象 | 含义 | 处理 |
|------|------|------|
| `Invalid tool parameters` | **参数名或类型错**，不是工具不可用 | 重读该工具的参数描述，按上表改一次再调；仍报错 → 把工具名、你传的参数、错误原文一起停下告诉用户 |
| 子 agent 返回空 / 被截断 | 运行时错误 | 原样重试一次；仍失败按阶段卡兜底，报告注明 |
| 子 agent 返回散文、没有 json 代码块 | 漏了 schema 尾注，或模型没遵守 | 先原样重试一次（强调只输出 json 块）；仍不行按兜底并在「待确认」注明 |
| `tools/contract-conformance.js` 全部 UNVERIFIED | 联调环境不可达或鉴权缺失 | 不是脚本坏了。检查 `--base-url` 与 `--header`；确实拿不到就接受 UNVERIFIED，⑦ 进人工清单 |
| `tools/out-of-scope.sh` 退出码 1 | 有越界文件 | 正常信号，不是错误。结果喂给 ⑥ |
| 子 agent 改了清单外的文件 / 顺手 commit | 人设里的变更边界没生效 | 报告里应有 `outOfScopeChanges`；用 `tools/out-of-scope.sh` 复核，越界文件回退后重跑该阶段；commit 由用户回退 |

**禁止的降级**：子 agent 工具连番报错时，不要「改用直接执行模式，自己在主上下文里完成分析 / 开发 / 评审」。那会把阶段产物和中间过程全灌进主上下文，③⑥⑦ 的评审也失去独立性。正确动作是停下来，把报错原文交给用户。

**时间戳**：每个阶段的报告落盘前用 `date -u +%FT%TZ` 取当前时间填入模板的时间字段。

## 三、模式 A 特有的错法（ Top 清单）

| 错法 | 后果 | 正确做法 |
|------|------|----------|
| 把 6/7 个维度串成一个子 agent 或串行派出 | 后面的维度看到前面的结论，独立性归零 | 同一条消息里并行发出全部调用 |
| 自己在主上下文里当评审员 / 开发者 | 主上下文既编排又执行，产物灌满上下文 | 每个角色都派子 agent；主上下文只做汇总 |
| 按 agent 回填的 `dimension` 字段对应维度 | agent 填错一个名字整张表归零 | 按派出顺序下标对应 |
| 跳过 `tools/*` 让 agent 自己判越界 / 自己打联调环境 | 把确定性检查变回 LLM 猜测 | 先跑脚本，结果作为入参 |
| 后端本地起 MySQL / Redis 凑证据 | 环境不可控，结论不可复现 | 需 DB 的路径标 `unverified`，等联调环境 |
| prompt 末尾漏掉 schema 尾注 | 拿回一段散文，无法汇总 | 尾注必填；解析不出先重试再兜底 |
| 凭记忆复述人设 | 版本漂移 | 每次按阶段卡 / `roles/fe-dev.md` 原文取 |
| 报告模板删段 | 续接时误判产物残缺 | 无内容写「无」，段落保留 |
| 在任何阶段执行 `git add` / `commit` / `merge` / `push` | 越过用户的提交权 | 只产出清单与命令 |
