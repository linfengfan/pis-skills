# 阶段卡 · deliver 交付说明

## 何时运行

主线终点：所有启用泳道的 test 都已完成或被用户接受。不派子 agent。

## 步骤

```bash
node <skill>/tools/state.js deliver --dir <d>
```

脚本把以下内容组装进 `<d>/deliver.md`：各阶段结果与分数、决策卡裁定、用户接受现状的取舍；每个仓的改动摘要、改动文件、越界文件（或「未判越界」）、开工前已有的改动、建议 commit message；必须人工验证的点（代码评审给出的验证点、未验证的验收标准、联调中未通过的接口）。

## 闸门

汇报：交付说明路径、每个仓的改动文件数与越界文件数、人工验证点数量。明确告诉用户：

- 流程到此结束，**没有执行任何 git 写操作**；是否提交、怎样提交、何时合入由用户决定。
- 越界文件建议先回退再提交；「开工前已有的改动」不属于本需求。
- 用户部署到联调环境后，可以说「已部署 + 网关地址」进入可选的联调阶段（`stages/integrate.md`）。

用户确认后 `state.js gate --dir <d> --stage deliver --choice next`。
