# just-flf · 全栈研发流程 Skill

给 Claude Code / Cursor 装上一条研发流水线：**需求梳理 → 接口梳理确认 → 方案 → 开发 → 代码评审 → 本地测试评估 → 交付说明**，部署后可选**联调**。每个阶段结束都停下来问你；评审用清单逐项判定、脚本算分；全程不碰 git 写操作，代码怎么提交由你决定。

- **适合**：新页面、新接口、跨前后端的功能。
- **不适合**：改一行文案、修一个单文件的明显 bug——直接让 AI 改。

| 你想做什么 | 怎么做 |
|-----------|--------|
| 安装 | 对 AI 说「读 `just-flf/INSTALL.md`，帮我装上」 |
| 卸载 | 对 AI 说「读 `just-flf/UNINSTALL.md`，彻底删掉」 |
| 开始一个需求 | 「用 just-flf 走一遍：<需求文档 / 原型链接 / 需求描述>」 |
| 继续上次的需求 | 「just-flf 继续」 |

## 工作区

推荐用一个 `.code-workspace` 把前端仓、后端仓放在一起：

```
~/dev/
├── team.code-workspace      ← folders: web-app / server-platform
├── web-app/                 ← 前端仓（.claude/fe-profile.md）
├── server-platform/         ← 后端仓（.claude/be-profile.md）
└── .just-flf/<需求短名>/     ← 流程产物（状态、报告、交付说明）
```

只开一个仓也能用（单仓模式），产物放在仓内的 `.just-flf/`，并写进本机的 `.git/info/exclude`，不影响共享的 `.gitignore`。打开的目录既不是 git 仓、也没有 `.code-workspace` 时，它会提示你创建。

## 流程

| 阶段 | 做什么 | 停下来问你什么 |
|------|--------|----------------|
| 需求梳理 | 台账、术语、场景矩阵与覆盖缺口、存量消费方、决策卡；判定分档（lite / full）与接口状态 | 决策卡逐张拍板；分档是否同意；后端仓这次能不能改 |
| 接口梳理确认 | 已有接口列复用清单；新增 / 变更接口定义字段、可空、错误码、幂等，前后端架构师各自把关 | 接口定义是否确认（之后改要升版本） |
| 方案（full 档） | 前后端架构师各出方案，3 个评审员按清单评审，不过自动修订 | 方案是否确认 |
| 开发 | 前端按接口定义生成 Mock 做 UI（先确认设计稿）；后端写接口与契约测试，本地编译 / 格式 / 单测通过 | 开发结果是否确认 |
| 代码评审 | 每个仓 3 个评审员（含本泳道架构师）；脚本算越界文件 | 不过时：回开发修复 / 接受现状 / 停 |
| 本地测试评估 | 先取证再评审；验收标准、回归、契约测试任一失败一票否决 | 同上 |
| 交付说明 | 每个仓的改动文件、越界文件、建议 commit message、必须人工验证的点 | 流程结束，提交由你决定 |
| 联调（可选） | 你部署后说「已部署 + 网关地址」：脚本校验接口（默认只读），前端换真接口 | 有失败接口时怎么处理 |

## 评分怎么算

每类评审有一份清单（`checklists/`），每条检查项有严重度：critical 3 分、major 2 分、minor 1 分。评审员逐项判 通过 / 不通过 / 不适用，不通过必须给位置和修法。分数 = 通过项权重 ÷ 适用项权重，**≥ 80 分且没有 critical 不通过**才算通过。清单之外的发现记为观察项，不计分——评审员没法凭感觉压分或抬分。

## 准备什么

| 东西 | 位置 | 缺了会怎样 |
|------|------|-----------|
| 前端 / 后端画像 | `<仓>/.claude/{fe,be}-profile.md` | 第一次用到时自动生成，请你确认 |
| 需求处理范式（可选） | 任意位置，第一次使用时告诉它 | 需求梳理按内置最小集执行 |
| 设计稿 / 原型链接 | 需求里或开发前给 | 涉及界面改动时会停下来要 |
| 联调凭证（联调时） | `~/.just-flf/auth`，每行一个 `Header: value`，权限 600 | 接口校验结果全是「未验证」 |

## 文件

```
just-flf/
├── SKILL.md          编排协议（模型读）
├── stages/           8 张阶段卡（编排者读）
├── roles/            10 张角色卡（子 agent 读）
├── checklists/       5 份评审清单
├── templates/        前端 / 后端画像模板
└── tools/            workspace.js / state.js / scope.js / conformance.js（Node ≥ 18，零依赖）
```

改流程看 `stages/`，改人设看 `roles/`，改评分标准看 `checklists/`，每类内容只在一处。
